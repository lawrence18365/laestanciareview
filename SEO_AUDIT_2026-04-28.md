# RateTap SEO Audit - 2026-04-28

## Executive Summary

RateTap has the beginnings of a useful SEO footprint, but it is not yet acquiring meaningful non-branded traffic. The Google Search Console export shows 39 clicks and 179 impressions over 54 reported days, with visible query traffic almost entirely branded (`ratetap`, `rate tap`). That means people who already know the name can find it, but the site is not yet reliably capturing restaurant operators searching for the problem.

The biggest near-term opportunities are:

1. Fix URL canonicalization and internal linking so Google sees one version of each page.
2. Fix broken localization and schema issues so crawlers trust the technical signals.
3. Improve homepage performance, especially the 2.1 MB logo image used at tiny display sizes.
4. Expand thin money pages into real buyer-intent pages.
5. Build a Spanish-first Mexico content cluster around restaurant Google reviews, staff performance, NFC cards, and reputation recovery.
6. Tighten conversion capture so organic visitors become demo/WhatsApp leads.

This is not a "publish more blog posts" problem first. The site needs technical cleanup and stronger bottom-of-funnel pages before content volume will compound.

## Critical Technical Findings

### P0 - Clean URL and `.html` versions both return `200`

Evidence:

- `https://ratetapmx.com/` returns `200`
- `https://ratetapmx.com/index.html` returns `200`
- `https://ratetapmx.com/case-studies` returns `200`
- `https://ratetapmx.com/case-studies.html` returns `200`
- `https://ratetapmx.com/demo` returns `200`
- `https://ratetapmx.com/demo.html` returns `200`
- `https://ratetapmx.com/restaurant-review-management-software` returns `200`
- `https://ratetapmx.com/restaurant-review-management-software.html` returns `200`

Local crawl found:

- 467 internal links containing `.html`
- 176 internal links containing `index.html`
- 27 structured-data URL fields still using `.html`

Search Console already confirms this is not theoretical: Google is reporting impressions for `/case-studies.html`, `/es/roi-calculator.html`, `/roi-calculator`, and `/index.html`.

Impact:

- Ranking signals split across duplicate URL variants.
- Google may choose a different canonical than the one declared.
- Internal links send mixed signals.
- Clean URLs in the sitemap conflict with `.html` links in the site chrome.

Fix:

1. Pick clean URLs as canonical URLs, because that is what sitemap and canonicals mostly use today.
2. Replace all internal `.html` and `index.html` links with clean absolute paths:
   - `demo.html` -> `/demo`
   - `index.html#features` -> `/#features`
   - `case-studies.html` -> `/case-studies`
   - Spanish pages should use `/es/...`
3. Update JSON-LD URLs to clean URLs.
4. Add server-level 301 redirects from `.html` to clean URLs.
5. If GitHub Pages cannot handle the redirect policy cleanly, put Cloudflare in front with redirect rules or move the marketing site to Cloudflare Pages, Netlify, or Vercel.

Google treats canonicals as strong hints, not absolute commands. Redirects, sitemaps, internal links, and canonical tags should all point to the same URL.

### P0 - Broken internal link to `/medir-desempeno-meseros`

Evidence:

- `blog/track-server-review-performance.html` links to `../medir-desempeno-meseros`.
- Live URL `https://ratetapmx.com/medir-desempeno-meseros` returns `404`.
- The English canonical page appears to be `/track-waiter-performance-dashboard`.
- The Spanish canonical page is `/es/medir-desempeno-meseros`.

Fix:

- On the English blog page, change links to `/track-waiter-performance-dashboard`.
- On Spanish pages, keep `/es/medir-desempeno-meseros`.
- Fix the source in `content/blog/posts.json` so regenerated pages do not reintroduce it.

### P0 - `methodology.html` references missing Spanish hreflang target

Evidence:

- `methodology.html` declares `hreflang="es-MX"` pointing at `https://ratetapmx.com/es/methodology`.
- Live URL `https://ratetapmx.com/es/methodology` returns `404`.
- There is no local `es/methodology.html`.

Fix options:

1. Create a Spanish methodology page and add it to the sitemap.
2. Or remove the `es-MX` alternate from `methodology.html` until the page exists.

Google's hreflang guidance requires each language version to list itself and its alternates. Broken alternates reduce trust in the locale cluster.

### P0 - Invalid JSON-LD on four money pages

The following pages contain invalid JSON-LD because of trailing commas:

- `get-more-google-reviews-restaurants.html`
- `nfc-google-review-cards-for-restaurants.html`
- `stop-bad-restaurant-reviews.html`
- `track-waiter-performance-dashboard.html`

Impact:

- Google may ignore the structured data on these pages.
- These are important commercial pages, so invalid schema is unnecessary risk.

Fix:

- Remove trailing commas.
- Validate with Google's Rich Results Test after deployment.
- Add schema validation to the build workflow if the static site stays hand-authored.

### P1 - Spanish pages often link users and crawlers back to English pages

Examples:

- Many `/es/...` pages use nav brand links like `../index.html`, which resolves to the English homepage.
- Several Spanish CTAs point to `../demo.html`, which resolves to English `/demo.html`, not `/es/demo`.
- Some Spanish blog links point to legacy noindex aliases like `/es/nfc-google-review-cards-for-restaurants` instead of canonical `/es/tarjetas-nfc-restaurantes-mexico`.

Impact:

- Spanish users can be pulled into the English funnel.
- Internal link equity leaks from the Spanish cluster to English pages.
- Hreflang and canonical signals become less clean.

Fix:

- Spanish nav logo: `/es/`
- Spanish demo CTA: `/es/demo`
- Spanish NFC card page: `/es/tarjetas-nfc-restaurantes-mexico`
- Spanish staff dashboard page: `/es/medir-desempeno-meseros`
- Spanish bad reviews page: `/es/evitar-malas-resenas-restaurante`

### P1 - Private/app pages are indexable

The following app pages lack title/description/canonical controls and are not noindexed:

- `app/admin.html`
- `app/dashboard.html`
- `app/feedback.html`
- `app/review.html`

They are not in the sitemap, but robots allow all crawling. If Google discovers them from QR flows, backlinks, browser sharing, or logs, they can enter the index.

Fix:

- Add `<meta name="robots" content="noindex,nofollow,noarchive">` to admin/dashboard flows.
- For public review/feedback QR pages, decide whether they should be indexed. In most cases, they should be `noindex,follow` because they are utility flows, not acquisition pages.
- Consider moving app flows to a subdomain with explicit index controls.

## Conversion Audit

SEO traffic only matters if it turns into leads/subscribers.

### Current positives

- Forms post to `formsubmit.co/hello@ratetapmx.com`.
- `script.js` attempts to add attribution fields to `#contact-form` and `#demo-form`.
- CTAs exist on most pages.
- `contacto.html` has a strong Spanish lead form with WhatsApp field.

### Current risks

1. `contacto.html` form uses `id="lead-form"`, but the global attribution logic only targets `form[data-lead-form], #contact-form, #demo-form`. That means the Spanish contact page may miss UTM/source hidden fields.
2. `contacto.html` shows success even if the AJAX request fails. That may hide real lead loss.
3. `demo.html` asks for a preferred date. That is friction for cold organic traffic.
4. The English demo form requires first name, last name, restaurant, email, and date. For SEO leads, a simpler first step usually converts better.
5. Several Spanish CTAs point to English demo pages unless JavaScript rewrites them.
6. Footer social/privacy/terms links are `#`, which reduces trust.

Fix:

- Make the primary organic CTA "Get a free restaurant review audit" or "Start a free pilot", not just "Book demo".
- Offer WhatsApp click as the Spanish primary CTA.
- Use one short form on money pages:
  - Name
  - Restaurant
  - City
  - WhatsApp
  - Optional email
- Track:
  - CTA clicks
  - Form starts
  - Form submits
  - WhatsApp clicks
  - Thank-you page views
  - Source page and source cluster
- Do not show success on network failure unless the lead was stored elsewhere.

## Bottom Line

RateTap can get SEO subscribers, but the current organic base is almost entirely branded. The fastest path is not broad blogging. It is:

1. Clean the crawl/index signals.
2. Make the Spanish commercial pages genuinely useful.
3. Use real proof from the 12-location deployment.
4. Convert visitors with a lower-friction Spanish-first lead flow.
5. Build authority through case studies, local proof, and restaurant-specific comparisons.

Once those foundations are fixed, content can compound. Without them, new posts will keep fighting mixed URLs, thin commercial pages, slow load, and weak conversion capture.
