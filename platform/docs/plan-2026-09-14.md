## What shipped in this pass (2026-09-14)

Three new event names in `src/lib/product-events.ts`:

| Event | Fired from | Closes |
|---|---|---|
| `review_screen_shown` | `StarRating.tsx` mount, client | loads that actually offered the stars |
| `review_blocked_local_guard` | `StarRating.tsx` mount, client | loads the 12h guard turned away |
| `review_submit_suppressed` | `api/reviews/submit/route.ts`, server | submits the 24h device cap dropped |

Exactly one of the first two fires per mount, so
`review_page_open − review_screen_shown` is now the guard's cost, per unit, per
day. The two client events carry `session_id` (`rt_sid`, per-tab) and a
`restaurant_slug` — `track()` gained an `opts.restaurantSlug` because guest
surfaces have no session for the endpoint to attribute against. A storage
exception counts as a **pass**, not a block: the stars render, so it emits
`review_screen_shown`.

`review_submit_suppressed` is awaited rather than fire-and-forget — the response
ends the serverless invocation, and a dropped insert is exactly the blind spot
the event exists to close.

Label fix: "Escaneos" → "Calificaciones" in the owner and regional weekly emails
(4 sites incl. the subject line) and in the 6 `location-signal.ts` summary
strings, which would otherwise have contradicted the tile directly above them.
One test pinned the old string and was updated.

`(app)/quotes/not-found.tsx`: `/quotes/[id]` calls `notFound()` for a deleted or
foreign quote, which surfaced as a bare 404 — indistinguishable from "the
section is broken". It now names the cause and links back to the list, so the
next report from Memo is diagnostic either way.
